# fluid2d 迁移教程

> 文档日期：2026-09-17
> 适用版本：当前 `fluid2d/` C++11 核心

本文说明如何把 `fluid2d` 接入 ESP32、STM32、其他 MCU 或 PC 工程。迁移的原则是：平台提供内存、重力、时间和显示，`fluid2d` 只运行 FLIP/PIC 模拟。

## 1. 需要加入工程的文件

核心只有两个编译输入：

```text
fluid2d/
├── fluid_solver.h
└── fluid_solver.cpp
```

工具链最低要求为 C++11。核心不要求 ESP-IDF、FreeRTOS、异常、RTTI、线程或动态容器；已经验证可以使用 `-fno-exceptions -fno-rtti` 编译。

如果使用本仓库的 CMake：

```cmake
set(FLUID2D_BUILD_TESTS OFF CACHE BOOL "" FORCE)
add_subdirectory(path/to/embedded-fluid2d/fluid2d)
target_link_libraries(your_application PRIVATE fluid2d)
```

也可以直接把 `fluid_solver.cpp` 加入平台工程，并把仓库根目录加入头文件搜索路径，以解析 `<fluid2d/fluid_solver.h>`。

## 2. 配置求解器

先从默认配置开始，只修改平台确实需要改变的资源参数：

```cpp
#include <fluid2d/fluid_solver.h>

fluid2d::Config config;
config.grid_width = 16;
config.grid_height = 16;
config.max_particles = 436;
config.pressure_iterations = 10;
config.particle_push_iterations = 1;
config.flip_ratio = 0.9f;
```

主要参数如下：

| 参数 | 作用 | 对资源的主要影响 |
| --- | --- | --- |
| `grid_width`, `grid_height` | 去掉边界 padding 后的可见网格尺寸 | RAM 和压力求解 CPU |
| `max_particles` | 粒子数组固定容量 | RAM |
| `pressure_iterations` | 每帧压力迭代次数 | CPU |
| `particle_push_iterations` | 每帧粒子互斥迭代次数 | CPU |
| `flip_ratio` | `0` 为 PIC，`1` 为 FLIP | 模拟稳定性和流动感 |
| `initial_fill_width`, `initial_fill_height` | 初始粒子填充范围 | 初始粒子数量 |
| `particle_radius_factor` | 粒子半径相对网格间距的比例 | 粒子数量和邻域开销 |
| `neighbor_spacing_factor` | 粒子邻域网格间距 | RAM 和粒子搜索开销 |
| `gravity_scale` | 输入重力的缩放值 | 运动强度 |
| `fluid_density` | 压力计算使用的流体密度 | 数值行为 |
| `pressure_over_relaxation` | 压力超松弛系数 | 收敛速度和稳定性 |
| `compensate_drift` | 是否补偿密度漂移 | 数值行为 |

当前求解器使用单一网格间距 `h`，即要求网格单元近似为正方形。以下比例相差超过允许误差时，配置会被拒绝：

```text
simulation_width / (grid_width + 2)
约等于
simulation_height / (grid_height + 2)
```

当前已经完整验证的是 `1.0 × 1.0` 模拟区域和 `16 × 16` 可见网格。

## 3. 准备 workspace

solver 不拥有内存。必须先查询当前配置所需字节数，再由平台准备连续、可写的 workspace：

```cpp
const std::size_t required =
    fluid2d::FluidSolver::requiredMemory(config);

if (required == 0) {
    // 配置无效，不能继续初始化。
}
```

不要把某个平台测出的字节数永久写死。指针大小和对齐规则会使 PC、32 位 MCU 和 64 位平台的结果略有不同。

### 静态内存方式

适合无 heap 或希望固定 RAM 上限的 MCU：

```cpp
#include <cstddef>

alignas(std::max_align_t)
static unsigned char workspace[32U * 1024U];

if (required > sizeof(workspace)) {
    // 降低网格、粒子容量，或增大静态数组。
}
```

### 平台内存池方式

ESP32 可以在应用层使用 `heap_caps_malloc()`，STM32 可以使用静态内存池，PC 可以使用 `std::vector<unsigned char>`。这些分配方式只能出现在平台或应用层，不能放进 `fluid2d`。

workspace 必须至少保持有效到 solver 停止使用为止。workspace 释放、复用或离开作用域后，solver 和已有 view 都不能继续访问。

## 4. 初始化

```cpp
fluid2d::FluidSolver solver;

const fluid2d::Status status =
    solver.initialize(config, workspace, sizeof(workspace));

if (status != fluid2d::Status::Ok) {
    // InvalidConfig 或 InsufficientMemory。
}
```

初始化成功后，网格尺寸和粒子容量固定。修改这些容量参数需要重新准备 workspace 并重新初始化。

迭代次数和 FLIP 比例可以在不重新分配内存的情况下调整：

```cpp
solver.setSolverQuality(1, 10, 0.9f);
```

## 5. 实时循环

平台层每帧只需要提供二维重力和 `dt`：

```cpp
void updateFluid(float gx, float gy, float dt) {
    solver.setGravity(gx, gy);

    const fluid2d::Status status = solver.step(dt);
    if (status != fluid2d::Status::Ok) {
        // dt 必须为有限正数，并且 solver 必须已经初始化。
    }
}
```

核心不会读取 timer、延时、创建 task 或加锁。以下工作都属于平台层：

1. ESP32 从 MPU6050 获取 `gx`、`gy`；
2. STM32 从自己的 IMU 驱动或固定方向得到重力；
3. PC 从鼠标、键盘或脚本得到重力；
4. 平台计算或固定 `dt`；
5. 平台决定何时调用 `step()`。

当前 ESP32 应用使用固定 `dt = 1 / SIM_FPS`。迁移初期建议保持原帧率和固定步长，不要同时改变时间模型。

## 6. 读取粒子

```cpp
const fluid2d::ParticleView particles = solver.particles();

for (std::size_t i = 0; i < particles.count; ++i) {
    const float x = particles.positions_xy[2U * i];
    const float y = particles.positions_xy[2U * i + 1U];
    const float vx = particles.velocities_xy[2U * i];
    const float vy = particles.velocities_xy[2U * i + 1U];
}
```

这些指针直接引用 workspace，不拥有数据。调用方只能读取，不能释放或修改它们。

## 7. 读取密度网格

```cpp
const fluid2d::GridView density = solver.densityGrid();

for (std::size_t x = 0; x < density.width; ++x) {
    for (std::size_t y = 0; y < density.height; ++y) {
        const float value = density.values[x * density.stride + y];
    }
}
```

密度视图已经跳过外围一圈 padding，但 `stride` 仍然包含 padding，因此不能使用 `x * height + y` 代替上面的索引公式。

核心输出的是原始模拟密度。LED、LCD 或 PC 显示映射必须留在应用层。

要保持旧 ESP32 水流灯的亮度观感，可以在应用层继续使用原映射：

```cpp
float normalized = density.rest_density > 0.0f
    ? value / density.rest_density
    : 0.0f;
float brightness = clamp(normalized / 1.2f, 0.0f, 1.0f);
brightness = std::pow(brightness, 0.6f);
float led_level = brightness * 20.0f;
```

调色板、RGB 转换、蛇形走线和 LED 下标换算继续由显示层处理。

## 8. 从现有 ESP32 C 代码迁移

现有 `water_sim.c` 是 C 文件，不能直接持有 C++ 类。迁移时有两种最小方式：

1. 将平台适配文件改为 `.cpp`，直接调用 `fluid2d::FluidSolver`；
2. 保留 `water_sim.c`，增加一个很薄的 `.cpp` C binding。

推荐先使用第二种方式，避免同时重写现有任务、按键和 LED 逻辑：

```cpp
// fluid2d_bridge.cpp
#include <fluid2d/fluid_solver.h>

extern "C" int water_fluid_init(void);
extern "C" int water_fluid_step(float dt, float gx, float gy);
extern "C" const float* water_fluid_density(void);
```

bridge 只负责：

- 保存 `FluidSolver` 和 workspace；
- 把 C 函数参数转给 C++ 核心；
- 返回密度视图需要的数据；
- 把 `Status` 转换成应用可处理的整数或平台错误码。

bridge 不能复制 FLIP/PIC 算法，也不能把 ESP-IDF 类型传进 `fluid2d`。

现有固件在创建 solver 后调用的是：

```text
push iterations     = 1
pressure iterations = 10
FLIP ratio          = 0.9
gravity scale       = 9.81
fill height         = 0.6
```

其中 `Config` 的压力迭代默认值是 `12`，它对应旧 `flip_create()` 内部默认值；要复现当前 `water_sim.c` 的实际运行参数，适配层必须将压力迭代改成 `10`。

## 9. ESP-IDF 构建接入

可以把核心作为独立 component，也可以由适配 component 直接编译。独立 component 的最小 `CMakeLists.txt` 形式为：

```cmake
idf_component_register(
    SRCS "path/to/embedded-fluid2d/fluid2d/fluid_solver.cpp"
    INCLUDE_DIRS "path/to/embedded-fluid2d"
)

target_compile_features(${COMPONENT_LIB} PUBLIC cxx_std_11)
```

`fluid_solver.cpp` 必须由 C++ 编译器编译。最终链接也必须包含 C++ 运行库；ESP-IDF 会在工程存在 `.cpp` 源文件时处理这一点。

## 10. STM32 和其他 MCU

1. 在工程中启用 C++11 编译；
2. 用 C++ 编译器编译 `fluid_solver.cpp`；
3. 将仓库根目录加入 include path；
4. 使用 C++ linker 完成最终链接；
5. 可以关闭异常和 RTTI；
6. 用静态数组提供 workspace；
7. 先使用较小网格、粒子容量和迭代次数；
8. 在目标板上测量每帧时间后再提高质量参数。

当前核心使用 `float`、`sqrt`、`floor` 和 `isfinite`。没有硬件 FPU 的 MCU 仍可编译，但每帧性能需要在目标板上实际确认。当前阶段不包含 fixed-point 实现。

## 11. PC 主机验证

迁移到新平台前，先在 PC 上验证相同配置：

```sh
cmake -S fluid2d -B build/fluid2d \
  -DCMAKE_CXX_STANDARD=11 \
  -DCMAKE_CXX_EXTENSIONS=OFF
cmake --build build/fluid2d
ctest --test-dir build/fluid2d --output-on-failure
```

平台适配完成后至少检查：

- `requiredMemory()` 不为零；
- `initialize()` 返回 `Ok`；
- 粒子数量符合预期；
- 连续运行后位置、速度和密度保持有限值；
- 显示层严格使用 `stride`；
- `step()` 期间没有 heap 分配；
- 重置后重新获取 particle/grid view；
- ESP32 参考应用的方向、亮度和帧率没有反转或漂移。

## 12. 当前限制

- 只提供浮点标量实现；
- 没有动态增删粒子；
- 没有任意障碍物编辑；
- 没有内部 timer、substep 或线程同步；
- 同一个 solver 不能由多个任务并发调用；
- 非方形区域必须配置为近似正方形网格单元，否则初始化配置无效；
- `dt`、重力和调参值必须保持在数值稳定范围内；
- DOOM Fire 是独立模块，不通过 `FluidSolver` 迁移，接入方式见 [`火焰迁移教程.md`](火焰迁移教程.md)。

完成这些步骤后，平台代码只负责输入、调度、内存和输出；后续修改 FLIP/PIC 算法时，不再需要接触 ESP-IDF、FreeRTOS、LED 或 IMU 驱动。
