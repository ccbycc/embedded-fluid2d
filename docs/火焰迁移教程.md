# DOOM Fire 迁移教程

> 文档日期：2026-09-17

`doom_fire` 是独立的 C++11 热度场效果核心。它不依赖 `fluid2d`，也不负责 LED、调色板、IMU、timer 或任务调度。

## 1. 加入工程

需要编译：

```text
doom_fire/doom_fire.h
doom_fire/doom_fire.cpp
```

使用 CMake 时：

```cmake
set(DOOM_FIRE_BUILD_TESTS OFF CACHE BOOL "" FORCE)
add_subdirectory(path/to/embedded-fluid2d/doom_fire)
target_link_libraries(your_application PRIVATE doom_fire)
```

也可以直接将 `doom_fire.cpp` 加入 MCU 工程，并把仓库根目录加入头文件路径，以解析 `<doom_fire/doom_fire.h>`。

## 2. 配置与内存

```cpp
#include <doom_fire/doom_fire.h>

doom_fire::Config config;
config.width = 16;
config.height = 16;
config.decay = 3.0f;
config.intensity = 36.0f;
config.max_heat = 80.0f;

const std::size_t required =
    doom_fire::DoomFire::requiredMemory(config);
```

`requiredMemory()` 返回 `0` 表示配置无效。当前算法保留旧实现的12行火源几何，因此 `height` 不能小于12。

无 heap 的 MCU 可以使用静态 workspace：

```cpp
#include <cstddef>

alignas(std::max_align_t)
static unsigned char fire_workspace[4U * 1024U];

if (required > sizeof(fire_workspace)) {
    // 降低网格尺寸或增加静态内存。
}
```

实际需要的字节数应在目标平台调用 `requiredMemory()` 获取，不要直接依赖示例数组大小。

## 3. 初始化

```cpp
doom_fire::DoomFire fire;

const doom_fire::Status status = fire.initialize(
    config,
    fire_workspace,
    sizeof(fire_workspace),
    random_seed);
```

seed 由应用层提供：

- ESP32 可以使用 `esp_random()`；
- STM32 可以使用硬件 RNG、ADC 噪声或保存的启动计数；
- PC 测试应使用固定 seed，保证结果可复现；
- seed 为 `0` 时，核心会改用 `1`。

核心不调用任何平台随机数 API。

## 4. 每帧推进

```cpp
fire.step(gravity_x, time_ms);
```

调用方负责提供：

- `gravity_x`：火焰水平倾斜输入；
- `time_ms`：用于摆动和呼吸效果的时间值。

当前 ESP32 应用会先执行：

```cpp
gravity_x = clamp(sensor_gx * 2.5f, -2.5f, 2.5f);
time_ms = esp_timer_get_time() / 1000;
```

这些转换继续保留在平台层。核心不会读取 MPU6050、系统 timer 或创建 FreeRTOS task。

## 5. 读取热度网格

```cpp
const doom_fire::HeatView heat = fire.heatGrid();

for (std::size_t y = 0; y < heat.height; ++y) {
    for (std::size_t x = 0; x < heat.width; ++x) {
        const float value = heat.values[y * heat.stride + x];
    }
}
```

热度网格采用行优先布局，和 `fluid2d` 的 x-major 密度布局不同。必须使用 `y * stride + x`。

输出范围为 `0` 到 `max_heat`。颜色和亮度映射属于显示层。旧 ESP32 应用的映射流程为：

```text
原始热度
  -> 四舍五入为整数热度等级
  -> 限制到 0..80
  -> 查询 classic / blue / purple 调色板
  -> 限制 LED 最大亮度
  -> 垂直翻转和蛇形灯板下标映射
```

## 6. 从现有 C 应用接入

现有 `fire_sim.c` 可以保留，并增加一个很薄的 `.cpp` bridge：

```cpp
extern "C" int fire_core_init(unsigned int seed);
extern "C" int fire_core_step(float gravity_x, unsigned int time_ms);
extern "C" const float* fire_core_heat(void);
```

bridge 负责保存 `DoomFire`、workspace 和最近一次 `HeatView`。它不能复制火焰传播算法，也不能把 ESP-IDF 类型传入 `doom_fire`。

## 7. 重置和生命周期

```cpp
fire.reset();
```

`reset()` 清空两个热度缓冲区，但保留当前 RNG 状态，与旧实现一致。需要重新开始完全相同的动画时，应使用相同 seed 再次初始化。

workspace 必须在 fire 和所有 `HeatView` 使用期间持续有效。核心初始化和 `step()` 均不申请堆内存，也不提供线程同步；同一个实例不能由多个任务并发推进。

## 8. 验证

```sh
cmake -S doom_fire -B build/doom_fire \
  -DCMAKE_CXX_STANDARD=11 \
  -DCMAKE_CXX_EXTENSIONS=OFF
cmake --build build/doom_fire
ctest --test-dir build/doom_fire --output-on-failure
```

默认16×16配置使用固定 seed、变化重力和120个时间样本检查热度汇总指标，并验证相同输入下结果确定。golden 指标来自冻结的旧 C 实现，测试运行时不再启动旧算法逐格对照。
